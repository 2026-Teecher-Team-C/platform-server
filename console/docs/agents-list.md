# PC 현황 실제 API 연동

## 범위와 기준

- 브랜치: `feat/console-agents-api`, 통합 기준: develop `89fb381`.
- 기존 변경을 stash `73a7c0d2a8007bbbb0f876c4ec1177c51b5e6ac3`에 보존한 뒤 fast-forward하고 복원했다. 백업 stash는 삭제하지 않았다.
- 읽기 전용 PC 목록만 구현한다. PC 상세, 등록 토큰 발급, PC 상태 변경, 실제 Agent 등록과 하트비트 전송은 이번 범위가 아니다.
- 기존 블랙리스트와 YARA 화면은 develop에서 반영된 그대로 유지하고, 백엔드 소스는 수정하지 않았다.

## 코드 흐름

- `lib/api/agents.ts`의 기존 domain client와 공통 HTTP client를 사용한다. `getAgents()`가 hostname/status/osPlatform/page/size를 전달하고 `PageResponse`를 받는다. 빈 필터는 생략하지만 page=0은 보존한다.
- `AgentsPage.tsx`는 입력 중인 검색 값과 적용한 query를 분리한다. 조회 시 첫 페이지, 페이지 크기 변경 시 첫 페이지로 이동한다. 크기는 20/50/100이다.
- 요청 query와 refresh 번호로 요청을 식별한다. 이전 요청의 늦은 성공/실패는 cleanup으로 무효화한다. 동일한 진행 중 요청은 다시 제출하지 않으며 다른 검색 조건은 이전 요청을 대체할 수 있다.
- 재조회 중에는 마지막 성공 결과와 페이지 정보를 유지하고 200ms 이후에만 진행 안내를 표시한다. 처음 불러올 때만 전체 로딩 안내를 사용한다. 실패 시 이전 결과와 재시도 안내를 같이 표시하고 페이지 이동을 막아 다른 조건으로 이전 표를 넘기지 않게 한다.
- 마지막 페이지가 사라지면 존재하는 마지막 페이지로 보정해 재조회한다. 빈 결과도 실패와 구분한다.
- hostname, Agent ID, 운영체제, 버전, 상태, 마지막 하트비트를 표시한다. 하트비트 null은 `미수신`, 값이 있으면 수신 시각을 표시한다. 서버 상태를 그대로 표시하며 별도의 온라인/오프라인 판정을 만들지 않는다.
- 기본 정렬은 `last_heartbeat_at DESC NULLS LAST, agent_id ASC`다. hostname은 대소문자를 구분하지 않는 부분 검색이며 `%`, `_`도 일반 문자로 찾는다.
- `mocks/handlers/agents.ts`의 목록만 실제 서버의 응답, 필터, 정렬, 검증 범위에 맞췄다. 기존 상세/등록 토큰 mock은 이번 연동 범위에서 제외했다.
- jsdom을 테스트 의존성으로 추가해 실제 React effect와 입력/버튼 이벤트를 실행한다. MSW 계약 테스트의 인증 우회는 목록 계약 검증용이며 로그인 검증으로 간주하지 않는다.

## 검증

- 프론트 lint, production build, 자동 테스트 전체 103개 통과.
- 기존 서버 `AgentListRestIntegrationTest` 10개 통과. 이 서버 테스트는 기존 AdminApiClient로 인증된 목록 요청을 수행하며 프론트 로그인 폼 검증과는 다르다.
- 브라우저에서 mock 비활성임을 확인하고 실제 API와 첫 행 ID를 비교했다.
- 별도 QA DB에 준비된 합성 PC 36개를 사용했다. ACTIVE/INACTIVE/REVOKED 각각 12개, WINDOWS/MACOS/LINUX 각각 12개, 하트비트 미수신 6개다. 실제 Agent가 등록하거나 하트비트를 보낸 결과가 아니다.
- 기본 20개 → 다음 페이지 16개 → 이전 페이지 동일 순서, 50개 선택 시 36개, hostname+REVOKED+LINUX 결합 필터 4개, 빈 결과를 확인했다.
- 실제 API 36개 전체의 하트비트/null/동일 시각 ID 정렬과 잘못된 page/size/status/osPlatform의 400 응답을 확인했다.
- 실제 GET 응답 전달을 보류해 87ms에는 진행 표시 없음, 지연 후 이전 표/높이 유지와 진행 안내, 이후 검색 결과를 과거 응답이 덮지 않음을 확인했다.
- 의도적으로 통신을 차단해 이전 표와 오류/재시도, 이동 버튼 잠금, 복구 후 INACTIVE 12개 표시를 확인했다.
- 390/1024/1440px에서 페이지 전체의 가로 넘침이 없었다. 넓은 표는 내부 가로 스크롤을 사용한다.
- 루트, 블랙리스트, 인증, 기존 주석 worktree의 작업 상태와 변경 파일 해시가 작업 전과 같음을 확인했다.

## 수동 확인 환경

- 독립 리뷰 결과 보안/로직 차단 이슈 없음. 프론트 상호작용 테스트는 Node v26.9.0에서 실행했다.
- 테스트 의존성 jsdom 30.1.3의 Node 요구 범위는 `^22.22.2 || ^24.15.0 || >=26.0.0`이다. 오래된 Node 22/24 패치 버전에서는 설치/테스트가 실패할 수 있다.
- 비차단 보완 사항: mock의 Number 변환은 빈 size나 지수 표기처럼 화면에서 생성하지 않는 직접 쿼리에서 Spring 정수 바인딩과 다를 수 있다. 일반 페이지 이동과 크기 선택은 정수만 보내므로 현재 UI에는 영향이 없으며, 특수 입력까지의 정합성 확대는 남겨둔다.

- 화면: http://100.70.241.6:5180/agents
- 실제 QA API: http://100.70.241.6:18084
- 격리된 로컬 Compose 프로젝트: `teamc-console-remaining-qa`. 브라우저 확인은 인증을 끈 서버에서 수행했다. 전체 콘솔 인증 통합은 C4에서 확인한다.
- 조회 버튼을 눌러 필터를 적용한다. 페이지 이동, 50건 선택, REVOKED+LINUX 조건, 존재하지 않는 호스트 이름 검색을 확인할 수 있다.
- 커밋/push/PR 생성 없이 사용자 검토를 기다린다.
